# 赛前推荐质量修复报告（简版）

- 时间：2026-10-25 08:02–08:45（GMT+8）
- 环境：真实门店 3350241（早餐菜单，85 项在售），真实 MCP 核价，MiMo thinking=disabled
- 范围：只修排序与匹配缺陷；未重构引擎、未换模型、未改 UI 结构、未新增依赖

---

## 一、根因（四条，均在排序层，不在数据层）

1. **核价额度被最便宜的商品吃光**：有预算上限时，核价批次按参考价升序取前 40 个 → 35–45 区间内、高蛋白的候选没被核价，永远进不了结果。
2. **选择器首位固定取最低价**：帕累托代表与价格梯度的第一个方案都是"最便宜"，主目标（蛋白）没有优先权。
3. **差异化补充为凑数量引入偏离目标项**：一份 ¥8.50 油条被当成"一个价位档"。
4. **「无糖」没有进入解析**：既无偏好字段，也没有"含糖量不可核实"的提示。

## 二、修复内容（最小改动）

| 位置 | 改动 |
|---|---|
| engine.js | 核价批次按「目标区间 → 蛋白 → 预算」排序；「一顿饭」语境排除单件方案；主目标传给选择器；不可行时按放宽条件真实重搜并核价（≤5/约束、≤12 总计） |
| diversity.js | 首位由主目标决定（蛋白最大化→蛋白最高）；高蛋白场景低于最优蛋白 40% 的候选不得用于凑价位/凑数量 |
| daily.js | 区间内加分 1.2 → 2.5；新增无糖评分（只认名称里「无糖/零度/0 糖」）；无糖无法核实时给提示与结论说明 |
| intent.js / schema.js / rule-parser.js | 新增 `sugarFree` 偏好（原文词面回退，模型漏给也能识别）与 `mealContext`（一顿/一餐/正餐/套餐） |
| test/recommend-quality.test.js | 新增 5 项定点断言 |

## 三、三个原始输入的实测前后对比

| 组成 | 主食+小食+饮料 | 主食+小食+饮料（保持） |

| 项 | 修复前 | 修复后 |
