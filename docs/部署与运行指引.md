# 部署与运行指引

## 一、环境要求

- Node.js **≥ 22**（本项目在 Node 22 上验证；无需 npm install，零第三方依赖）
- 可访问 `https://mcp.mcd.cn` 的网络
- 可选：一个 OpenAI 兼容的模型端点（不配也能跑，会降级为规则解析）

## 二、本地运行（评委最省事的路径）

```bash
cd mcfits
cp .env.example .env  # 填写自己的凭证，勿提交
node src/http/server.js
# 打开 http://localhost:5173/          产品页
#      http://localhost:5173/console.html  工程验证台（数据诊断）
```

凭证按以下优先级自动解析，**只需满足其中一种**：

| 凭证 | 来源顺序 |
|---|---|
| MCP Token | 默认仅 `MCD_MCP_TOKEN`；仅 `MCFIT_ALLOW_LOCAL_MCP=1` 允许本机文件 |
| 模型 Key | 默认仅 `MCFIT_LLM_BASE_URL` + `MCFIT_LLM_API_KEY`；仅 `MCFIT_LLM_ALLOW_LOCAL=1` 允许本机模型配置 |

服务启动时会打印：

```
麦门营养决策官 · McFit Agent
  产品页   http://localhost:5173/
  工程台   http://localhost:5173/console.html
  API      http://localhost:5173/api/health
  门店     3350241 麦当劳济南凤鸣广场餐厅
  MCP      https://mcp.mcd.cn
  Token    已配置（WorkBuddy 服务端配置 本地开发者配置（不随仓库提供））
[prewarm] 池：套餐 28 / 单品 45 / 缺营养排除 40；参考价 66/73（1277ms）
```

预热完成后首个请求约 0.5 秒返回。（池内数量随门店实时菜单变化，上面是一次真实输出。）

## 三、局域网访问（同一 Wi-Fi 下的手机/另一台电脑）

1. 查看本机地址：`ipconfig` → 找到 IPv4（如 `<LAN-IP>`）
2. 手机浏览器访问 `http://<LAN-IP>:5173/`
3. 如果打不开，检查 Windows 防火墙是否允许 Node 入站（首次运行时会弹窗，选"允许专用网络"）

服务默认监听所有网卡（`listen(port)`），无需额外配置。

> 注意：局域网访问时，**任何人**都能使用你本机的模型额度。演示完毕请关闭服务，或按第五节限制额度。

## 四、生产环境配置（对外部署时）

```bash
NODE_ENV=production \
MCD_MCP_TOKEN=xxx \
MCFIT_LLM_BASE_URL=https://your-endpoint/v1 \
MCFIT_LLM_API_KEY=xxx \
MCFIT_LLM_MODEL=your-model \
PORT=5173 \
node src/http/server.js
```

**配置隔离**：服务加载仓库 `.env`，已有环境优先。任何模式均默认禁用本机配置，仅对应 ALLOW_LOCAL 开关为 1 时启用。

以下历史生产说明以该策略为准：`NODE_ENV=production` 时 `allowLocalConfig=false`，服务不会读取 `本地开发者配置（不随仓库提供）` 与 `本地开发者配置（不随仓库提供）`，避免公开访问者无控制消耗开发者个人额度。有测试用例（`test/production.test.js`）覆盖这一行为。

若确实要在生产模式下用本机配置（例如只在可信网络演示），可显式打开：

```bash
MCFIT_LLM_ALLOW_LOCAL=1 MCFIT_ALLOW_LOCAL_MCP=1 NODE_ENV=production node src/http/server.js
```

## 五、额度与滥用防护

| 项目 | 默认值 | 调整方式 |
|---|---|---|
| 自然语言解析 | 20 次/分钟/IP | `MCFIT_RL_PARSE` |
| 推荐（含核价） | 30 次/分钟/IP | `MCFIT_RL_RECOMMEND` |
| 套餐重算 | 60 次/分钟/IP | `MCFIT_RL_REBUILD` |
| 需求文本长度 | 500 字符 | `MCFIT_MAX_INPUT_CHARS` |
| MCP 并发 | 10（官方限流 600/分钟） | `MCD_MCP_CONCURRENCY` |
| MCP 超时 | 20 秒（失败重试 2 次） | `MCD_MCP_TIMEOUT_MS` / `MCD_MCP_MAX_RETRIES` |
| 价格缓存 | 5 分钟 | `MCFIT_TTL_PRICE_MS` |

超限返回 `429` + `Retry-After`。限流是单进程内存实现，多实例部署需换成共享存储。

> **额度归属**：自然语言解析的 token 消耗计入 `MCFIT_LLM_*` 所配置账号的额度；本机演示时计入开发者 WorkBuddy 授权账号。`/api/llm/status` 会返回 `sourceKind` 与 `quotaNote`，点击页面右上角模型徽章也能看到说明。

## 六、健康检查

```bash
curl http://localhost:5173/api/health
# {"ok":true,"mcp":{"reachable":true,"serverTime":"..."},"store":{...},"caches":{...}}
```

`/api/llm/status` 可看模型来源；加 `?probe=1` 会真发一次最小请求探测可用性。

## 七、本阶段的部署结论

**未做公网部署。** 原因：

1. 需要购买服务器并把第三方模型的付费额度暴露给公开访问者，属于需要用户明确授权的支出与风险；
2. 比赛材料可以用「可运行代码 + 本地指引 + 截图/录屏」满足，不必承担公网运维风险。

因此本轮交付的是**本地可运行版本**。若评委需要远程体验，推荐二选一：

- **局域网演示**（同 Wi-Fi 手机/笔记本访问，见第三节）；
- **视频 + 现场操作**（录屏脚本见 `docs/演示脚本.md`，所有镜头来自真实运行）。

如需正式上线，除第四节的配置外，还建议：HTTPS 反向代理（Nginx/Caddy）、进程守护（systemd/PM2）、固定门店与业务时段校验、更严格的单 IP 配额。

## 八、常见问题

**Q：启动后页面一直转圈 / 提示服务未就绪？**
看控制台是否有 `[prewarm] 跳过` 或 MCP 报错。多数是 Token 未配置或网络到 `mcp.mcd.cn` 不通。

**Q：价格为什么和昨天不一样？**
价格来自实时试算，缓存 5 分钟。历史报告里的金额（如麦香鱼单品 ¥23）与今天（麦香鱼中套餐 ¥34）是不同商品口径，不能直接比较。

**Q：为什么推荐里有的商品一直没有？**
官方营养表只有 160 条，覆盖不到部分新品；这些商品不参与营养计算（见页面「为什么推荐」中的说明与 `/api/coverage`）。
