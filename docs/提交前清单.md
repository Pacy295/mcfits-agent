# 提交前清单（需作者本人完成）

> 本文件只列**必须由你亲自做**的动作。开发侧已完成的部分见 `README.md` 与 `docs/`。
> 原则：不代你提交比赛、不公开部署、不开通付费服务。

## A. 录屏操作卡（约 2 分 30 秒，照着点即可）

**准备（录制前 5 分钟）**

1. 打开终端：`cd mcfits && node src/http/server.js`
2. 等到出现 `[prewarm] 池：套餐 ... / 单品 ...` 这一行（表示候选池与参考价已预热）
3. 浏览器打开 `http://localhost:5173/`，窗口 1440×900、缩放 100%
4. 确认右上角是绿色「解析：mimo-v2.6-pro」；开始录屏（保留浏览器地址栏）

**第一幕（约 50 秒）**

5. 输入框已有预填句：`预算 40 元，想吃高蛋白，热量不超过 750 大卡，最好有无糖饮料`
6. 点「开始配餐」→ 等到蓝色提示条出现（模型解析）→ 出现 4 张方案卡
7. 念一句："预算 40 是硬上限，高蛋白只是倾向，蛋白质下限没有被偷偷填成数字。"
8. 点第一张卡的「为什么推荐 · 数据来源」→ 展示 traceId 与营养口径 → 再收起

**第二幕（约 40 秒）**

9. 在第 1 张、第 2 张卡上各点一次「加入对比」
10. 念出底部那一句结论（**以屏幕为准**，不要念旧金额）："多花多少、多多少蛋白，系统直接算给我看。"

**第三幕（约 50 秒）**

11. 找一张写着「官方套餐」的卡 → 点「调整套餐」
12. 在「选择套餐内饮料」里选 **可乐大杯（+¥2.0）** → 等价格与热量刷新
13. 再在「选择套餐内小食」里选 **大薯条（+¥2.0）** → 再刷新一次（此时应为 ¥38.00 / 928 kcal 一组数，屏幕为准）
14. 念一句："营养是官方组件值相加，价格每次改动都重新调 calculate-price，traceId 会换新的。"
15. 展示抽屉底部的"特制无法计算营养"提示

**第四幕（约 40 秒）**

16. 关闭抽屉 → 条件面板改：预算 `12`、蛋白质下限 `45`、勾选「必须包含 → 饮料」
17. 等「这些条件凑不出一餐」出现 → 指着三条放宽结论和"超预算 ¥xx"逐行念一条
18. 念收尾："算得出来的给数字和来源，算不出来的说清为什么。"

**收尾**

19. 停止录屏；导出 1080p 或 720p 的 mp4，命名 `mcfits-demo-<日期>.mp4`
20. 若现场模型不可用出现黄色"已降级为规则解析"，不要紧，解说一句"这是可解释的降级"，不用重录

## D. 不要做的事

- 不要把 `MCD_MCP_TOKEN`、`MCFIT_LLM_API_KEY`、`本地开发者配置（不随仓库提供）`、`本地开发者配置（不随仓库提供）` 提交进仓库或贴进截图。
- 不要把 `cache/` 目录一起上传（里面有实时价格与 traceId，属运行数据，且会让人误以为是静态样例）。
- 不要在公开环境使用 `MCFIT_LLM_ALLOW_LOCAL=1`（会把个人额度暴露给任何访问者）。
- 不要把"当前已核价候选中最省钱"改写成"全麦当劳最省钱"——前者有边界，后者没有依据。
