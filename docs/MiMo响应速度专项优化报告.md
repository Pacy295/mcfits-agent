# McFit Agent · MiMo-V2.6-Pro 云端 API 响应速度专项优化报告

> 任务边界：只优化现有 MiMo-V2.6-Pro 的 API 调用速度/稳定性/解析效率。未更换模型、未重构架构、未修改配餐优化算法。
> 测试时间：2026-10-24。数据来源：`scripts/perf-llm-ab.mjs`（33 输入 × 2 轮 × 2 模式 = 132 次真实调用，绕过应用层缓存）+ `scripts/verify-perf-fixes.mjs` + `scripts/verify-stage5.mjs` + 89 项自动化测试。

## 1. 原来为什么慢（已证实的原因）

| # | 原因 | 证据 | 处置 |
|---|------|------|------|
| 1 | **深度思考默认开启**（主因）：请求体未显式传 thinking 参数，网关默认开启深度思考，每次解析平均消耗 165 reasoning tokens，长思考链带来长尾延迟 | A/B 对照：关思考后 P50 5847→2573ms、P95 15284→3587ms | 显式传 `"thinking":{"type":"disabled"}`（见第 2、11 项） |
| 2 | **输出偏长**：平均 completion 303 tokens，实测最长 818（逼近旧上限 900） | A/B token 统计；B 模式 completion 降至 138 | 输出上限模式感知（关思考 600 / 开思考 900），提示词精简 |
| 3 | **超时过长放大最坏等待**：旧 40s | 历史慢请求 43.6s 案例；A 模式 P95 达 15.3s | 已收紧 20s（MCFIT_LLM_TIMEOUT_MS 可覆盖） |
| 4 | **配置重复读盘**：每次调用/状态查询都重读 本地开发者配置（不随仓库提供） | 调用链检查 | 进程内 30s 缓存（MODELS_CACHE_MS 可调） |
| 5 | **401/403 无冷却重试**：无效凭证反复打端点 | 调用链检查 | 5 分钟冷却（AUTH_FAIL_COOLDOWN），期间标记 skipped_auth_cooldown |
| 6 | **错误分类缺失**：失败记录出现 `mimo-v2.6-pro(undefined)`，无法诊断 | 修复前 A/B 实测错误日志 | 全链路结构化分类（timeout/network/http/bad_output/bad_json/truncated/all_failed） |

## 2. 当前是否开启深度思考

- **优化前**：请求体未传 thinking 字段 → 网关默认**开启**深度思考（响应含 reasoning 链，reasoning tokens 均值 165）。
- **优化后默认**：**关闭**。请求体显式携带 `"thinking": {"type": "disabled"}`。
- **网关真实支持验证**（非仅 HTTP 200）：B 模式 66 次调用 `reasoning_tokens=0`、`reasoning_content` 消失，证据链完整。
- 不换 MiMo-Flash，凭证与服务条款未变动，无阻塞。

| min / max | 2214 / 19422 ms | 1638 / 3920 ms | 长尾大幅收敛 |

注：A 模式本轮 1 条断言波动（「不要辣」被开思考模型判为 hard≠soft，66 次中 1 次），B 模式两轮均 100%，详见第 8 项。

## 4. 提示词和请求参数的改变

1. **thinking 参数显式化**：默认 `{"type":"disabled"}`；`MCFIT_LLM_THINKING=enabled|default` 时不传字段（完整回退到原始行为）。
2. **输出上限模式感知**：关思考默认 max_tokens=600（实测 completion max=159，约 4 倍余量）、开思考 900；`MCFIT_LLM_MAX_TOKENS` 可覆盖。截断由 finish_reason=length 监控，实测 0 截断。
3. **提示词/JSON 精简**：SCHEMA_DOC 不再要求模型输出 hardConstraints/softPreferences（改由解析层派生），仅保留解析必需字段，不删任何校验所需信息。
4. **temperature=0、response_format=json_object 不变**（任务书要求先确认生效再动，故不动）。
5. **超时 20s**（此前已收紧），`MCFIT_LLM_TIMEOUT_MS` 可覆盖。
6. **保留**：数值反幻觉校验、语义校验、双路解析、规则降级，全部原样。

## 5. 首次请求 P50/P95 对比（模型 API 响应加速）

- P50：5847 → 2573 ms（**-3274 ms，2.27×**）

## 6. 完整推荐总等待时间变化（用户总等待减少）

verify-stage5 真实链路实测（自然语言 → 解析 → MCP 核价 → 推荐，B 模式新代码）：

| 场景 | 解析 | 推荐 | 端到端 |
|---|---|---|---|
| A 日常一句话点餐 | 3223 ms | 2230 ms | **5.5 s** |
| B 不适与口味偏好（问题现场） | 4061 ms | 690 ms | **4.8 s** |
| C 精准营养多目标 | 1486 ms | 2063 ms | **3.5 s** |
| F 不可验证偏好 | 1659 ms | 1983 ms | **3.6 s** |

**严格区分**：
- 模型 API 响应加速：2.27×（P50）/ 4.26×（P95）。
- 用户总等待减少：解析环节是大头，优化前仅解析 P50 就需 5.8s（端到端普遍 8~20s，最坏 40s+）；现在端到端 3.5~5.5s，**总等待约减半**。推荐环节（MCP 核价 0.7~2.2s）与算法本轮未动，故总等待的改善比例小于模型 API 的提速比例——如实呈现，不用缓存命中数字充数。

## 11. 最终采用的参数配置及回退方法

**默认配置（新）**：
```js
thinking: { type: 'disabled' }   // 显式关闭深度思考
max_tokens: 600                  // 关思考档（开思考档 900）
temperature: 0
response_format: { type: 'json_object' }
timeout: 20000ms
```

**回退方法**（全部环境变量可切换，无需改代码）：

| 操作 | 配置 |
|---|---|
| 回退到原始思考模式 | `MCFIT_LLM_THINKING=enabled`（不传 thinking 字段，恢复网关默认） |
| 调整输出上限 | `MCFIT_LLM_MAX_TOKENS=<n>` |
| 调整超时 | `MCFIT_LLM_TIMEOUT_MS=<n>` |
| 关闭模型调用（纯规则解析） | `MCFIT_LLM_DISABLE=1` |
| 配置重读缓存 | `MCFIT_LLM_CONFIG_TTL_MS=<ms>`（默认 30000） |

**有限条件回退**（质量保护）：budgetIntent 仅在原文存在词面证据（classifyBudget 判定 `intentSource='raw-regex'`）时纠正模型输出，无证据保留模型语义判断；若后续发现关思考导致复杂语义质量下降，可整档回退 `MCFIT_LLM_THINKING=enabled`，其余优化不受影响。

**保留未动**：双路解析、规则降级、数值反幻觉、预算语义、MCP 核价、多方案优化、交互式套餐替换、LRU 200/TTL 10min/并发去重、生产密钥隔离、全部 UI 与接口契约。
